# قاعدة التنفيذ الذاتي — قرار المستخدم الأخير (ملزم لكلود)

**طلب المستخدم:** «وقوله ميرجعلش خالص غير لما يخلص كل حاجه وتبقا جاهزه علي الشغل ولو وقع في لوب ينهيه ويشوف طريقه يطلع منه ولو التيرمنال وقف يستخدم طريقه تانيه غيره».

## السياسة العملية
- لا تطلب موافقة متكررة على ألوان وتفاصيل وقدرات سبق اعتمادها في الملفات. واصل التنفيذ مرحلة وراء مرحلة، واعتبر مرور أول Build ناجح بداية الاختبارات وليس نهاية المشروع.
- لا تُرجع للمستخدم خطة نظرية أو صور فقط؛ يجب إنهاء أكواد الواجهة والخلفية وقاعدة البيانات والتكاملات والأمان والاختبارات، بأقصى قدر تسمح به البيئة الفعلية.
- راقب توقيع الأخطاء واللوب: بعد محاولتين فاشلتين متشابهتين، **غيّر المسار**؛ لا تعيد نفس prompt/terminal command أو نفس JSON بلا دليل جديد.
- سقوط التيرمنال: بدائل متاحة فعلًا مثل File APIs، IDE edit tools، Git connector، test runner مستقل أو حاوية محلية مصرح بها. لا تفترض وجود SSH أو صلاحيات غير حقيقية.
- عند فشل مزود AI أو نقص مفاتيحه، أنجز وحدة Provider Hub **الداخلية لمشرفي OnTrack فقط** وحالات الفشل والاختبارات الوهمية الصحيحة ثم انتقل فورًا لباقي وحدات المنتج. عدم وجود اتصال مباشر ليس سببًا لتعطيل التسويق والـCRM والـAuth والـKnowledge.
- إذا أمكن الوصول لموقع Staging مُصرَّح به، انشر باحتياطيات وقابلية رجوع وتحقق end-to-end. لا تلمس Production أو بيانات WHMCS الحية دون سند صريح؛ لا تنشر حالة `CONNECTED_LIVE` دون إثبات.
- عند أي حاجز **غير قابل للحل** بعد استنفاد البدائل، أنهِ كل ما يمكن مستقلاً وسلّم تقريرًا محددًا بالأجزاء التي تعمل والتي تنتظر أسرارًا/إعدادًا خارجيًا. لا تستبدل التحفّظ بتأكيدات كاذبة.
- سجّل جميع نقاط التقدم في `docs/IMPLEMENTATION_STATUS.md` وجداول الاختبار، وأبقِ تحديثات التنفيذ متواصلة عند توفر نافذة زمنية، ولا تتعهد بعمل غير متزامن دون وسيلة فعلية تدعمه.

## شرط النهاية
نهاية العمل ليست `أنشأت ملفات` ولا `نجح composer install`، بل نظام Laravel قابل للتشغيل، ومراحل حقيقية مكتملة وموثقة بقدر الوصول، ونتيجة اختبارات، وقائمة العوائق الخارجية الباقية فقط. مرجع التفصيل: `docs/DELIVERY_PHASES_TESTS_AR.md`.
