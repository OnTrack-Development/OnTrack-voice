# OnTrack Voice — بروتوكول التطوير الذاتي الدوري
تاريخ الاعتماد: 2026-11-01. طلب المالك تشغيل متابعة آلية كل ساعة **بعد انتهاء تحديث القرارات الحالي**. هذا الملف يعبر عن التعليمات، وليس إثبات أن الجدولة فعالة حتى يظهر Task ID من الخدمة.

## مصدر الحقيقة وترتيب القراءة
1. `AGENTS.md` ثم `CLAUDE.md`.
2. `docs/discovery/OWNER_APPROVED_MASTER_DECISIONS_2026_11_01_AR.md`.
3. `docs/memory/CHECKPOINT.md` ثم `docs/plan/IMPLEMENTATION_PLAN_AR.md`.
4. Code `main`, open PRs, CI وworkflow publishing، والأدلة الحديثة على الهوست.
5. تجنّب إعادة تنفيذ مهمة منتهية أو التعارض مع PR مفتوح/تشغيل سابق.

## خطوة التشغيل الذاتي الواحدة
1. افحص آخر commit/PR/workflow وحالة المهمة الأولى غير المغلقة، ثم اختر **مشكلة واحدة** قابلة للتنفيذ والاختبار في جلسة التشغيل.
2. افحص المصدر الفعلي وأعد إنتاج المشكلة باختبار أولًا (عند الإمكان)، ثم عدّل الكود الحقيقي في فرع مستقل صغير؛ لا تكتفِ بوثيقة أو برومبت.
3. نفّذ اختبارات unit/integration/CI المناسبة، وسجّل دليل النجاح/الفشل. لا تَدّعِ E2E للأجهزة أو حساب خارجي لم تختبره.
4. عند نجاح اختبارات CI المطلوبة ومراجعة الفروقات وعدم وجود تغييرات حساسة غير مختبرة: افتح PR وادمجه، وتحقق من سير النشر والـhost receipt قبل ادعاء النشر.
5. **قيود الأمان:** لا تنشر تغييرًا خطرًا في الإنتاج دون rollback واختبارات staging، ولا تُجري مكالمة فعلية أو تخصم رسومًا حقيقية أو تُنشئ مفاتيح مالية/تسوية أو تحذف بيانات نهائيًا تلقائيًا. إذا احتاجت مهمة اتصالًا بموبايل أو حسابًا حقيقيًا أو تفويض طرف آخر، اتركها BLOCKED مع السبب، وانتقل لأصغر مهمة مستقلة متاحة.
6. حدّث `docs/memory/CHECKPOINT.md` وملف حالة التنفيذ بعد نجاح حقيقي أو عائق واضح: المشكلة، السبب، الملفات، commits، CI runs، host receipt، الاختبار على الجهاز إن وُجد، ما لم يثبت، الخطوة القادمة. لا تغيّر التاريخ أو تكتب نتيجة اختبار لم تحدث.
7. ارفع للمستخدم ملخصًا عمليًا موجزًا: ما تغيّر، رابط PR/commit، نتائج الاختبار، Blocker/Next. لا تعلن 'المشروع مكتمل' بسبب نجاح CLI فقط.
8. إن كان أول بند غير قابل للاختبار فلا تلف في حلقة API أو تستنزف الموارد؛ انتقل لبند مستقل قابل للإغلاق.

## تصنيف الإثبات
- `SPEC_APPROVED`: المالك اعتمد المطلوب.
- `CODED`: تغيير محفوظ في GitHub.
- `CI_PASS`: Workflow محدد ونتيجته `success`.
- `HOST_DEPLOYED`: Receipt مباشر من host/runner يذكر commit.
- `AUTH_UI_VERIFIED`: جلسة فعلية موثقة على الموقع بنطاق الصلاحيات.
- `DEVICE_E2E_VERIFIED`: مكالمة واقعية مسجلة أحداثها على هاتف محدد، في الوارد والصادر.
- `PAYMENT_E2E_VERIFIED`: بوابة Test موقعة ومعاملة حقيقية sandbox انتهت بلا تكرار أو تسرب.
- `BLOCKED`: دليل واضح على النقص والأثر والشرط اللازم.

## منع التصادم
اقرأ PRs المفتوحة على `OnTrack-Development/OnTrack-voice`؛ لا تعدل ملفات يغيرها تشغيل آخر دون مزامنة Git. استخدم اسم فرع واضح، لا تمس الأسرار ولا سجلات المعاملات، ولا تعتمد على remembered GitHub SHA قديم.

## عناصر ليست أدلة نجاح
- نجاح PHP lint لا يعني أن WHMCS SSO يعمل.
- وصول HTTP200 للـlogin لا يعني أن لوحة الأدمن اختُبرت بحسابه.
- نجاح demo WebView لا يعني أن صوت SIM مدعوم على كل Android.
- Webhook داخلي signed لا يعني أن Kashier نفسها أكدت التسوية.
