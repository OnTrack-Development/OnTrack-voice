# OnTrack Voice — تحديثات Android من داخل التطبيق (0.2.1)

## القرار
- UI OTA: تنزيل HTML موقَّع والتحقق من hash والتوافق، تشغيل الواجهة الجديدة دون إعادة تثبيت APK.
- إعدادات الإيجنت: المزامنة المباشرة مع خادم OnTrack؛ لا تحتاج تحديث APK.
- Native Android OTA: مع الإصدار 0.2.1، التطبيق يفحص إصدار Android عند فتح مركز الاتصال، ويعرض الإصدار الجديد عند توافره. زر «تحميل وتثبيت» ينزِّل APK من `https://app.ontrackegy.com/saas/mobile/updates/native/` ويتحقق من manifest بتوقيع RSA الموجود في شهادة التطبيق، وSHA256 للملف، وحجمه، وpackage ID، وversionCode، وبصمة شهادة APK. لا يتبع Redirect لمصادر خارجية.
- بعد التحقق يفتح مثبت Android الرسمي عبر FileProvider محدود داخل مساحة التطبيق؛ يتطلب إذن «التثبيت من هذا المصدر» عند الحاجة وموافقة المستخدم. **لا يوجد تثبيت Native صامت أو تغيير كود APK دون موافقة Android**.
- لا يبدأ Native install داخل مكالمة؛ يُبقي تنزيل APK مؤكدًا بعد السماح للتطبيق بالتثبيت، ويمكن إعادة الضغط لإتمام التثبيت.
- التطبيق يظل يحافظ على `com.ontrack.voiceproof` وشهادة توقيع APK الحالية، والتثبيت يكون فوق التطبيق الحالي دون محو الاقتران.
- **الانتقال من 0.2.0 إلى 0.2.1 يحتاج مرة واحدة ملف APK** لأن النسخة 0.2.0 لا تحتوي Native Update Manager. بعد 0.2.1 يتم تقديم الإصدارات اللاحقة من داخل التطبيق.
- لا يُطلَب Accessibility أو SMS/Notification Listener. `REQUEST_INSTALL_PACKAGES` لغرض التثبيت الاختياري فقط، وFileProvider مُقيّد بمجلد ملفات التحديث.

## تنفيذ CI والنشر
- APK code=12, versionName=0.2.1-ota.
- `tools/prepare_mobile_native.py` يبني manifest مرتبطة بالـAPK النهائي. `tools/SignMobileOta.java` يوقع manifest بالشهادة نفسها بعد Assert لبصمتها الثابتة.
- GitHub Actions يختبر المشروع على JVM/Android Emulator، يراجع توقيع APK، يُنشئ UI OTA7، ثم يُصدر native manifest.
- `tools/queue_mobile_native.py` ينشئ أمرًا للعامل البعيد بعد التأكد من اكتمال مهمة نشر UI. يحصل على رابط تنزيل GitHub Artifact مؤقت دون مشاركة `GH_TOKEN` مع الاستضافة. `native_deploy.py` يتحقق من signature/hash، ويثبت APK immutable على hosting، ثم ينشر `native/latest.json` أخيرًا.
- لا يُعتبر نشر Native ناجحًا إلا عند ظهور تقرير host `mobile-native-<run-id>.json` بنجاح، وفحص HTTP200 من خارج الاستضافة.

## اختبار القبول
1. تثبيت APK 0.2.1 فوق 0.2.0 (من غير Uninstall/clear data)، وتأكيد بقاء الاقتران/Key وقناة `mix`.
2. فتح صفحة «تحديثات OnTrack»، اختبار فحص Native، وحالة «Android محدّث» عند تساوي الإصدار المثبت مع المنشور.
3. اختبار إصدار Native مستقبلي أعلى عبر ملف Signed APK؛ تأكيد ظهور موافقة Android وعدم بدء تثبيت خلال مكالمة.
4. تغيير UI OTA عبر نشر revision8 مستقبلًا إلى Native 12، واختبار أن الواجهة تتغير بدون APK.
5. اختبار رفض manifest غير موقَّع أو APK بباكيدج/بصمة/شهادة مختلفة، ورجوع زر الواجهة إلى حالة مفهومة.
6. اختبار المزامنة On/Off، استلام مكالمة واحدة فقط، نقل Wi-Fi، دخول الأدمن بضغطة واحدة على هاتف المستخدم؛ هذه الوظائف من الإصدار السابق وتظل معايير قبول مستقلة.

## حدود المنصة
- قيود Android تمنع تجاوز موافقة المستخدم على تثبيت APK من تطبيق عادي (بدون Device Owner/MDM).
- اتصال الشبكة أثناء تنزيل الملف ضروري، وWi-Fi debugging/ADB قد يحتاج موافقة إضافية من النظام بعد إعادة تشغيل الهاتف أو تبديل Wi-Fi.
- عشرات الأجهزة/العملاء لاحقًا تحتاج استضافة نشر منفصلة، سياسة gradual rollout، retention، وإدارة مفاتيح توقيع production لدى OnTrack؛ لا يتم اعتبار شهادة debug الحالية مناسبة لإطلاق SaaS عام.
