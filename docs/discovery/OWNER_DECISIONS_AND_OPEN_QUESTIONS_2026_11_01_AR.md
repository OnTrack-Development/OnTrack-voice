# OnTrack Voice — قرارات المالك النهائية وأسئلة الإطلاق المفتوحة
**تاريخ:** 2026-11-01 (Africa/Cairo)  
**الحالة:** SIX_OWNER_DECISIONS_LOCKED / FURTHER_DECISIONS_PENDING  
**الأولوية:** هذا الملف أحدث من نصوص المقترحات المؤرخة 29–31 أكتوبر، وأي تعارض يُحسم بقرار المالك الأحدث المثبت هنا. لا تخلط وجود الكود بإثبات E2E حي.

## القرارات الستة النهائية المعتمدة (لا يُعاد السؤال عنها)
- **OV-001 — Responsive Web:** منصة SaaS موقع ويب كامل، نفس تصميم الديسكتوب؛ Sidebar تتحول إلى قائمة جانبية قابلة للفتح على الموبايل. ليست Bottom Navigation لتطبيق Android. Light/Dark والهوية الأحمر/الأسود/الأبيض.
- **OV-002 — Support Mode:** أدمن OnTrack المخوّل لديه صلاحيات صاحب حساب العميل أثناء جلسة الدعم فيما عدا الأسرار الحساسة، مع Audit Log يسجل الفاعل الحقيقي والحساب المستهدف؛ الريسيلر داخل عملائه فقط، دون صلاحية عابرة للعملاء. التفاصيل الحساسة غير المحددة ممنوعة مؤقتًا حتى اعتماد Q03.
- **OV-003 — Deletion:** سلة محذوفات (soft delete) + حذف نهائي حسب الصلاحية، وحفظ سجلات مالية/تدقيق لازمة. المدد ونطاق الصلاحيات لم تعتمد بعد (Q04).
- **OV-004 — Agent Flow:** AI مرن يلتزم بالأسئلة والشروط والمتغيرات، يجيب عن أسئلة خارج الموضوع، ثم يعود لنقطة التوقف دون تكرار، مع استئناف صحيح بعد المقاطعة. وجود محرر graph في قاعدة البيانات وحده ليس تشغيلًا أثناء مكالمة SIM.
- **OV-005 — Multi-Tenant Device Pairing First:** ربط Android والجهاز والشريحة بالمستأجر/الموقع/الإيجنت بشكل منفصل من البداية. يمنع استخدام مفتاح هاتف Pilot المشترك لمنح أي عميل صلاحية هاتف آخر. لا تدّعي اكتمال الربط قبل Device E2E.
- **OV-006 — Admin Login:** المالك لديه حساب أدمن يعمل واستخدم لوحة التحكم وأرسل منها التعديلات. عدم توفر جلسة دخوله للأداة ليس دليلًا على أن لوحة الأدمن لا تعمل؛ لا تُعد ضبط كلمة المرور أو تطلب إنشاء حساب جديد بلا سبب.

## قرارات سابقة مستمرة لا حاجة للسؤال عنها مجددًا
- **OV-007:** شريحة الهاتف الحالية وباقتها لاتصالات SIM الواردة والصادرة؛ لا إلزام Phone Link/Voicemeeter أو GSM hardware أو LiveKit أو Shizuku أو Accessibility أو عقد اتصال جديد. اختبار Xiaomi الفعلي شرط للميزات المرتبطة بالصوت.
- **OV-008:** كل شركة حساب مستقل؛ مواقع متعددة Agents/Knowledge/Flow/API خاصة بكل موقع حسب الباقة؛ Admin / Reseller / User؛ White Label للريسيلر على دومين موثق، ونفس ملفات التطبيق المركزية.
- **OV-009:** Contacts من الهاتف: الكل أو المحدد بموافقة؛ CSV/XLSX/TXT ولصق؛ حملات مؤقتة وساعات عمل/عطلات وتأخير بين المكالمات؛ استخدام الاسم متغيرًا؛ DNC/Consent/Opt-out إلزامي.
- **OV-010:** سجل مكالمات وتقرير وتقييم ونتيجة لكل رقم ومزامنة؛ لا تُختلق تسجيلات أو مكالمات.
- **OV-011:** أصوات Google + AYO Premium بعد readiness واختبار حقوق وتقنية؛ باقات ودفع Kashier مع test قبل live؛ لا تعلن أصواتًا غير مثبتة جاهزة.
- **OV-012:** PHP 8.3 ضمن saas/console على استضافة OnTrack، لا ترفع docs أو الأسرار إلى public_html؛ GitHub هو مصدر الكود والميموري، مع نشر وفحوص وrollback ودفتر نتائج.
- **OV-013:** OTA لواجهة WebView يمكن دون APK، أما تغييرات Android Native فتحتاج موافقة نظام التشغيل على التثبيت؛ لا تعد بتحديث APK صامت من تطبيق عادي.

## الأسئلة المفتوحة — إجابة المالك مطلوبة قبل القرارات التجارية/السلوكية المقابلة
- **Q01 — Milestone:** أي مسار يُسلّم أولًا مع اختبار شامل: (A) SaaS admin/reseller/user + multi-tenant device pairing + inbound end-to-end؛ (B) نفس ذلك ومع حملات outbound؛ (C) كامل SaaS بما فيه الدفع والتكاملات من أول إصدار.
- **Q02 — الحسابات:** إنشاء حسابات المستخدمين: (A) دعوة + تفعيل بريد/كلمة مرور؛ (B) تسجيل ذاتي ضمن Trial/خطة؛ (C) الاثنين؛ مع ضرورة 2FA لأدوار الإدارة؟
- **Q03 — دعم العملاء:** الدخول كعميل مباشرة بعد سبب موثق أم يطلب قبول العميل؟ وهل يَحظر على الدعم اعتماد المدفوعات أو حذف/تصدير التسجيلات أو تغيير الأجهزة، بالإضافة إلى كشف المفاتيح وكلمات المرور؟
- **Q04 — سلة المحذوفات:** مدة الاحتفاظ قبل الحذف النهائي (مثلاً 30/90 يومًا/يدوي)، ومن يحق له الحذف النهائي (مالك الحساب/Platform Admin فقط/تفويض مستقل)؟
- **Q05 — Pairing:** أسلوب ربط الأجهزة (QR/رمز مؤقت/كلاهما)، وضرورة تحقق رقم الشريحة والتحويل لجهاز بديل؟
- **Q06 — خطوط وأجهزة:** هل جهاز واحد قد يحتوي شريحتين لحسابين/موقعين؟ وهل يحق نقل الخط بين الأجهزة مع إلغاء اعتماده على الجهاز القديم فورًا؟
- **Q07 — Android:** الأجهزة المستهدفة لبدء دعم مُعتمد بعد Xiaomi (Xiaomi فقط Pilot/باقي الشركات بعد matrix/أي Android 12+)؛ لا تعمم قبل التحقق.
- **Q08 — الوارد مع الصادر:** مكالمة واردة أثناء حملة: توقف الاتصال التالي حتى انتهاء الوارد أم توقف الحملة كلها أم سياسة اختيارية؟
- **Q09 — تعيين الإيجنت:** خط/رقم واحد له إيجنت ثابت أم اختيار حسب ساعات العمل/IVR/رقم المتصل؟
- **Q10 — فشل AI/الشبكة:** إن انقطع AI في مكالمة نشطة هل يتم التحويل البشري، أم تنبيه/إنهاء آمن، أم سياسة لكل خط؟
- **Q11 — التحويل البشري:** المقصود استلام الإنسان على نفس هاتف SIM (حاليًا) أم تحويل مباشر لرقم موظف خارجي أيضًا عند الإمكانية؟
- **Q12 — التسجيل والخصوصية:** تشغيل التسجيل افتراضيًا أم Opt-in حسب كل شركة؟ هل تنبيه المتصل قبل التسجيل؟ مدة حفظ الصوت والنص ومن يحق لهما الاطلاع/التصدير؟
- **Q13 — النتيجة والتقرير:** اعتماد تصنيفات ثابتة (مهتم/غير مهتم/متابعة/لا تتصل مجددًا...) أم قابلة للتخصيص لكل حملة؟ هل يلزم مراجع بشري قبل أي متابعة؟
- **Q14 — المزود الصوتي والـAI:** Gemini Live يبقى محرك الاتصال الحالي للمراحل الأولى أم لوحة اختيار Providers/Models للأدمن من البداية؟ تحديد إن كان استعمال Google/غيره ممولًا بمفاتيح OnTrack فقط كما في القرارات السابقة.
- **Q15 — Flow Lifecycle:** اعتماد Draft → Test → Publish → Version/Rollback؛ هل المكالمات الجارية تظل على نسخة البدء؟ ما سياسة Fallback عند شرط غير واضح؟
- **Q16 — Knowledge:** مدخلات المعرفة المطلوبة أولًا (نص/ملفات PDF-DOCX/روابط مواقع/Google Drive) وهل تحديث المصدر تلقائي أم يدوي؟
- **Q17 — جدولة الحملات:** حد retries وفاصل المحاولات، أوقات العمل الافتراضية بتوقيت العميل أم القاهرة، وماذا يحدث للأرقام busy/no-answer؟
- **Q18 — جهات الاتصال:** استيراد الهاتف مرة واحدة بالاختيار أم مزامنة دورية صريحة؟ أين تُحفظ الأسماء وهل يمنع رفع جهات بلا موافقة؟
- **Q19 — الباقات:** العملة EGP فقط أم متعددة؟ شهري وسنوي وتجريبي؟ حدود الخطة بالمكالمات المجابة أم دقائق الصوت أم الاثنين؟ إيقاف عند نفاد الحصة أم شراء زيادة؟
- **Q20 — المحاسبة والبوابة:** Kashier أولًا فقط مع قابلية إضافة Gateways، أم أكثر من Gateway من أول إصدار؟ هل الدفع اليدوي واسترداد/إلغاء المدفوعات جزء من الأولوية الحالية؟
- **Q21 — الريسيلر:** هل الريسيلر يحدد أسعار البيع لعملائه ويحصلها بنفسه، أم OnTrack تحصلها، أم وضعان وفق الاختيار؟
- **Q22 — WHMCS/Laravel:** من مصدر الحقيقة للاشتراكات في الحسابات المربوطة: منصة OnTrack أم WHMCS/Laravel الخارجي؟ قنوات إشعارات التفعيل/الفشل/التجديد المفضلة؟
- **Q23 — الإطلاق:** هل يُسمح بحسابات Demo معزولة على موقع التشغيل، أم لوحة staging منفصلة؟ ومن يصرّح بإجراء مكالمات اختبار فعلية غير تجريبية؟
- **Q24 — معايير القبول:** ما الأجهزة/المتصفحات ذات الأولوية لاختبار Responsive، وعدد الحسابات والخطوط المطلوبة في E2E قبل وصف النسخة بأنها مستقرة؟
