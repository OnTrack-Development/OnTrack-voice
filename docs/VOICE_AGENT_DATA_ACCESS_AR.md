# OnTrack Voice — مصادر المعرفة والتكاملات وصلاحيات المتصلين

## الحدود الفعلية في هذه المرحلة

- **Flow Builder:** دعم عقدة `instruction` الموجودة في جميع القوالب، ملء الشاشة، اقتراح مخطط من AI، مراجعة مفصلة، وتطبيق اختياري على **مسودة**. نشر السيناريو إلى SIM/Google Live ما زال خطوة منفصلة.
- **المعرفة المحلية:** مصدر نص أو ملف `.txt` / `.md` / `.csv` / `.json` بحجم لا يزيد عن 180KB، محفوظ في قاعدة OnTrack SaaS لكل حساب وموقع، ويُستخدم في المخطط والمحادثات الجديدة لذلك الموقع. ليست ملفات PDF/DOCX مفهرسة بعد.
- **تكاملات القراءة:** WordPress REST / Laravel HTTPS API / WHMCS GetProducts / Custom REST. إنشاء التكامل يبدأ `draft`؛ تفعيله فقط بعد اختبار حي ناجح `verified`. المصادر المختبرة يمكن أن تدعم اقتراح المخطط ببيانات مُرشّحة (كتالوج/محتوى عام)، ولا تعني وصولًا عامًا لبيانات العملاء.
- **صلاحيات الهاتف:** رقم دولي واحد أو أكثر لكل موظف موجود بالفعل في الحساب، مع صلاحيات قراءة محدودة حسب عضويته ومحددة لكل رقم. `PIN` محفوظ بهَش ويفرض قفلًا بعد خمس محاولات فاشلة لمدة 15 دقيقة. **الرقم وحده ليس توثيقًا**.
- **ما لم يُفعّل:** سماع/تحليل PIN عبر DTMF أثناء مكالمة حقيقية، الاستعلام التفاعلي عن تذاكر أو فواتير أو حجوزات محمية من Google Live، إجراءات الحجز والإلغاء أو إيقاف المواقع أو تعديل WHMCS/WordPress/Laravel. `voice_action_ready` يرجع `false` حتى بناء مُنفذ أوامر مصرح ومختبر.

## نموذج البيانات والصلاحيات

مساحة OnTrack Voice الحالية تعمل بلوحة PHP/SQLite أو MySQL مستقلة عن تطبيق Laravel الموجود في الريبو. ملفات Laravel ومعرفته وتكاملاته **ليست** مرتبطة تلقائيًا بقاعدة الإنتاج الحالية. كل مصدر يحدد `account_id` و`site_id`، ويجب تأكيد عضوية المستخدم قبل إضافته.

موظف الاستقبال: `general/bookings/tickets`. المحاسب: `general/finance`. المدير: `general/tickets/bookings/websites/operations`. صاحب الحساب: كل نطاقات القراءة المسموح بها؛ أي تخفيض للصلاحيات في عضوية الحساب يسري عند التحقق التالي. البيانات الحساسة لا تُرجع لمتصل بناءً على Caller-ID فقط.

## طريقة ربط نظام خارجي

1. صاحب الحساب يحدد الموقع ونوع الربط وعنوان HTTPS عام ومسار قراءة محدد ومفتاحًا محفوظًا مشفرًا إن لزم.
2. يتم اختبار الربط على السيرفر: عنوان عام فقط، تثبيت IP بعد فحص DNS، منع التحويلات وTLS مطلوب، حجم استجابة محدود.
3. WordPress يستخدم REST GET ويمكن ربط Application Password؛ Laravel وCustom يستخدمان GET لمسار قراءة مسجل مسبقًا؛ WHMCS يُسمح له حاليًا بـ`GetProducts` فقط.
4. لا يسمح العميل الصوتي أو النموذج بتقديم URL جديدة أو أسماء API Actions أو طلبات كتابة مباشرة.
5. أي طلب بيانات محمية يتطلب تعريف الدور، تحقق PIN/عامل إضافي، فلترة صلاحيات على كل نتيجة، وتسجيل أثر تدقيق.

## إجراءات مستقبلية

تنفذ أوامر مثل `booking.create` أو `website.disable` فقط عند وجود Tool Manifest مثبت ومختبر: مستخدم موثّق، صلاحية لكل عملية ومورد، موافقة صريحة أو تأكيد ثنائي مناسب للخطورة، `idempotency key`، تدقيق بدون أسرار، حدود معدلات، إلغاء/تعويض عند الإمكان. لا يجوز تنفيذ الأمر من نص نموذج AI مباشرة.

## التحقق

`tools/test_flow_ai_sources.php` يتحقق من عزل المعرفة، عدم السماح بعنوان خاص أو HTTP أو traversal، بقاء الربط مسودة قبل اختبار حي، عدم تصدير سر إلى سياق AI، ورفض عقد الكتابة المقترحة من النموذج. `tools/test_voice_access.php` يفحص هوية الموظف والـPIN ومجال الاطلاع ورفض العمليات الحساسة. لا يغني أي من هذه الاختبارات عن تجربة مكالمة حقيقية عندما يتوفر مسار DTMF والاستعلامات.
