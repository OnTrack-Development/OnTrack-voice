# OnTrack SaaS — اعتماد أمان الصيانة من دون فقد الخدمات (9 نوفمبر 2026)

**الحالة:** إجراء مطلوب على الهوست قبل نشر أي تعديل لهذه الدفعة. هذه الوثيقة لا تنشر ولا تغيّر أي سر.

## القاعدة
- لا تلمس APK أو OTA أو SIM أو مفاتيح Google/Fish/IO/Omnira الحالية أو اشتراكات/حسابات العملاء.
- ملف `UPLOAD_TO_ROOT.txt` كان يحتوي سر صيانة منشورًا في تاريخ Git. تعتيم النسخة الحالية **ليس تدويرًا**؛ يجب تدوير السر على الهوست ومراجعة تاريخ المستودع وسجلات الوصول، دون نسخه للتوثيق.
- `api/setup_demo.php` يقبل `POST` فقط مع `X-Maintenance-Token`؛ المفتاح الجديد في **POST body** وليس GET.
- `api/diag.php` يحتفظ بطريقة `GET` مع `X-Maintenance-Token` في Header فقط.
- `omnira_api_tester.php` يحتفظ بكل اختبارات Basic/Stream/Tools/Models لكنه يتطلب Basic Auth: اسم المستخدم `ontrack-maintenance` وكلمة المرور سر الصيانة الجديد، بالإضافة إلى CSRF تلقائي.
- إذا لم يكن Digest الصيانة مُثبتًا على الهوست، سترجع هذه الأدوات `503` بدل فتح مسار غير مصادق. **هذا مانع نشر** لحين تجهيز إجراء إدارة بديل والتأكد من الاستعمال المشروع.

## خطوات تجهيز الاستضافة (بواسطة مسؤول الهوست، وليس داخل Git)
1. خذ Snapshot وإيصال Host SHA ونسخة تراجع قابلة للاستعادة للملفات/الداتا الحالية؛ اعرف أي سكربت/Operator يعتمد بالفعل على `diag.php` أو `setup_demo.php`.
2. من جلسة SSH آمنة بحساب الاستضافة، أنشئ سر صيانة قويًا **جديدًا** واحفظه في Password Manager فقط. لا تضعه في أوامر Shell History أو URL أو GitHub Actions Logs.
3. اقرأ السر من STDIN عند تنفيذ `php tools/provision_maintenance_token.php`؛ الكود يكتب SHA-256 فقط بصلاحيات `0600` في `/home/appontrack/.ontrack-maintenance/token.sha256` ويضبط المجلد `0700`. **لا تطبع السر أو الـDigest في logs**.
4. تحقق محليًا من وجود الملف وملكيته وسلوك مصادقة Header باستخدام اختبار لا يعرض السر. جرّب GET التشخيص المصرح وPOST الإعداد على بيئة الاختبار فقط، وتأكد أن المفتاح الحالي للديمو لم يتبدل دون قصد.
5. اختبر رفض `?token=` و`?key=`، ورفض الطلبات غير المصرحة `401/403`، وحدود الطلبات `429`، وتأكد من استمرار اختبار Omnira بالأزرار الأربعة بعد Basic Auth.
6. ابحث عن نسخ من `UPLOAD_TO_ROOT.txt` أو `dev_bridge.php` في Webroot، وأزل **الوصول العام غير المصرح** بعد توفير مسار إداري محمي؛ لا تحذف أداة تعمل قبل اختبار البديل.
7. لا تدوّر أو تحذف `demo_config.local.php` القديم أو سر Gemini أثناء الانتقال. التهيئة الجديدة تُحفظ في `/home/appontrack/.ontrack-demo/demo_config.php` (خارج Webroot) مع استمرار قراءة Legacy config إن لم يوجد ملف جديد.
8. راجع تاريخ Git والتسريبات المحتملة مع صاحب المستودع، ثم أبطل السر القديم؛ إثبات `old credential denied` إلزامي. لا تعيد كتابة تاريخ Git أو force-push دون خطة إعادة استنساخ وتعهد بعدم إسقاط الفروع الموثقة.
9. لا تعلن DONE حتى مقارنة وظائف Root Demo/Outbound وTenant Live/SIM/Auth/SSO وHost SHA مع النسخة السابقة على موقع الاختبار والهوست المقصود.
