# OnTrack Host Link

قناة إدارة لحساب `appontrack` باستخدام Python 3.9+ وGitHub HTTPS.
الهوست يسحب مهمة من فرع `ontrack-host-link` كل دقيقة ويرفع تقرير JSON إلى نفس الفرع.
لا تحتاج SSH واردًا أو Node أو Asterisk أو root، ولا تعرض endpoint لتنفيذ الأوامر على الويب.

## التركيب

1. أنشئ Fine-grained personal access token من إعدادات GitHub، واختر Resource owner: `OnTrack-Development`، ثم Only select repositories: `OnTrack-voice` فقط، وصلاحية Repository permissions → Contents: Read and write. صلاحية Metadata Read تُضاف تلقائيًا. اختر مدة قصيرة مناسبة للاختبار، مثل 7 أيام. إذا كانت سياسة المؤسسة تتطلب الموافقة، يجب اعتماد التوكن قبل التركيب.
2. شغّل أمر التركيب الذي أُرسل مع هذا الإصدار داخل Terminal لحساب `appontrack`. أدخل التوكن في المطالبة المخفية؛ لا ترسله في المحادثة. ينزّل الأمر نسخة مثبتة برقم commit ويتحقق من SHA-256، ثم يحفظ العامل وإعداداته داخل `~/ontrack-voice-link` بصلاحيات خاصة وخارج public_html.
3. المثبّت يشغّل أول مهمة فورًا ويتحقق من رفع نتيجتها قبل إضافة Cron كل دقيقة مع الحفاظ على المهام الموجودة. إذا كان أمر crontab غير متاح، يطبع سطر Cron لإضافته يدويًا من cPanel.

المصدر الرسمي لصلاحية Contents المطلوبة: https://docs.github.com/en/rest/repos/contents#create-or-update-file-contents

## التشغيل

- المهمة: `ops/host-link/jobs/appontrack-server11.json` على فرع `ontrack-host-link`.
- التقارير: `ops/host-link/results/appontrack-server11/<job-id>.json`.
- أول مهمة `bootstrap-probe-20261029` تفحص الأدوات وأسماء العناصر في public_html فقط، دون قراءة إعدادات الموقع أو الاتصال بعملاء.
- لإرسال مهمة جديدة، استبدل ملف المهمة بمعرف جديد وتوقيت UTC صالح لمدة أقصاها 7 أيام. مهمة واحدة في كل مرة؛ انتظر تقريرها قبل استبدالها. اجعل المعرف فريدًا ولا تستخدمه مجددًا.
- الإجراءات: `probe` أو `exec` مع `argv` كقائمة. لا يوجد shell ضمني؛ لتشغيل سكربت استخدم البرنامج ومساره كعناصر القائمة.
- مهلة exec: من 1 إلى 30 ثانية. بعد خروج الأمر، تُغلق أيضًا العمليات التابعة في مجموعته؛ لا تستخدمه لتشغيل daemon في الخلفية. للخدمات الطويلة نحتاج طريقة تشغيل مناسبة لدى مزود الاستضافة.

مثال لشكل مهمة فحص PHP؛ يجب وضع created_at/expires_at فعليين قبل إرسالها:

```json
{
  "schema": 1,
  "id": "php-check-UNIQUE",
  "target": "appontrack-server11",
  "action": "exec",
  "created_at": "CURRENT-UTC-ISO8601",
  "expires_at": "ONE-HOUR-LATER-UTC-ISO8601",
  "cwd": "/home/appontrack/public_html",
  "argv": ["/usr/local/bin/php", "-v"],
  "timeout_seconds": 10
}
```

## حدود الوصول والاعتمادية

العامل ينفذ الأوامر بصلاحيات حساب الاستضافة الحالي. هذا وصول فعلي إلى الحساب؛ أصحاب صلاحية الكتابة إلى فرع الأوامر يستطيعون إرسال أوامر. التحقق من cwd ليس sandbox ولا يمنع برنامجًا داخل المهمة من الوصول إلى ملفات أخرى متاحة لنفس المستخدم. لا يمنح العامل صلاحيات root أو صلاحيات خارج حسابه.

التوكن يبقى في config.json محلي بصلاحية 600، ومجلد العامل 700. لا يُرفع إلى المستودع أو يُمرر إلى بيئة البرامج التابعة. يُحجب التوكن وأنماط GitHub tokens وBearer وPEM private keys المعروفة من التقارير؛ هذا ليس كاشفًا عامًا لكل أسرار المشروع. لا تُرسل مهام تطبع ملفات الأسرار كاملة أو بيانات العملاء. التقارير المخزنة في المستودع الخاص تظل متاحة لمن له حق قراءته.

قفل محلي يمنع تداخل تشغيل Cron. يسجل العامل بداية المهمة قبل تنفيذها ويحفظ النتيجة قبل رفعها. فشل رفع التقرير يعيد محاولة الرفع دون إعادة تنفيذ الأمر. التعطل أثناء التنفيذ يعرض `interrupted_unknown` ولا يعيد الأمر تلقائيًا؛ افحص أثره قبل إصدار أمر جديد. ليس هناك ضمان لإتمام جميع الآثار مرة واحدة إذا انقطع البرنامج؛ الضمان هنا هو تجنب إعادة التنفيذ تلقائيًا.

الحالات: `success`، `failed`، `timeout`، `interrupted_unknown`. يتم قص stdout وstderr إلى 32 KiB لكل منهما. التقرير مرتبط بـ SHA-256 لملف المهمة. عدم ظهور تقرير لا يعني فشل الأمر أو نجاحه.

## الإيقاف والاستئناف

```sh
touch ~/ontrack-voice-link/STOP
# استئناف:
rm ~/ontrack-voice-link/STOP
```

للإزالة: احذف سطر Cron المنتهي بـ `# ontrack-voice-link`، وألغِ التوكن من GitHub. إزالة STOP ليست مطلوبة أثناء الإزالة. لإيقاف exec مع الإبقاء على الفحص، اضبط `allow_exec` إلى false في config.json.

يمكن تشغيل tick واحد يدويًا:

```sh
/bin/python3 ~/ontrack-voice-link/worker.py
```

فشل التوكن أو انتهاء صلاحيته أو انقطاع وصول الهوست إلى api.github.com يوقف تبادل المهام. `last-run.log` يعرض آخر خطأ محلي دون توكن.

## التحقق

```sh
python3 -m unittest discover -s ops/host-link/tests -v
```

الاختبارات المحلية تشمل عدم تكرار الآثار بعد فشل رفع التقرير، والتعافي بعد التعطل دون إعادة التنفيذ، والمهلة حتى بعد إغلاق المخرجات، وقص المخرجات، وحجب التوكن، ورفض المهام المنتهية أو المعرف المتكرر بمحتوى مختلف.

نجاح هذه الاختبارات يثبت سلوك القناة محليًا فقط. إثبات الاتصال الفعلي يحتاج تقريرًا مرفوعًا من حساب الهوست. هذه القناة ليست تكامل صوت ولا تثبت تمرير صوت شريحة الهاتف.
