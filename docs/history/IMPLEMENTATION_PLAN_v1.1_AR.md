# خطة تنفيذ قسم الاتصالات الذكية — OnTrack Voice

الإصدار: 1.1 — 29 أكتوبر 2026

تحديث معتمد: أرقام خدمة الشركات أرقام موبايل حقيقية للوارد والصادر. المسار المقترح للشريحة هو GSM/VoLTE Gateway، مع إبقاء ربط مباشر من شركة المحمول خيارًا مشروطًا بتوفر خدمة موثقة على رقم الموبايل نفسه.

الحالة: تخطيط تنفيذ مبني على الملفات المرفقة والقرارات المعتمدة في المحادثة. لا يمثل كودًا منفذًا أو اتصالًا هاتفيًا تم اختباره.

## 1. النتيجة المطلوبة

قسم مستقل داخل OnTrack AI Agent Builder، يوفر لكل شركة موظف اتصالات بالذكاء الاصطناعي، ورقم موبايل خدمة مستقلًا، ومعرفة ومهام وقوائم عمل ودوامًا وتقارير تخصها وحدها.

أي شخص يتصل برقم الشركة يصل للإيجنت المرتبط به. والإيجنت يستطيع الاتصال بأرقام العملاء تلقائيًا أثناء الدوام، وتدوين الملاحظات أثناء الحديث، وإعداد تقرير بعد كل مكالمة، ثم انتظار الفاصل المحدد قبل الاتصال بالرقم التالي. يستمر التشغيل والسيرفر يعمل حتى مع إغلاق جميع المتصفحات.

## 2. القرارات المعتمدة وحدود النسخة

- الاعتماد على مشروع voicecall الحالي ومحرك Gemini Live المستخدم فيه. يحتفظ المشروع بالمصرية وشخصية الإيجنت وتعليماته ومهامه؛ جودة المكالمة الهاتفية الفعلية تحتاج اختبارًا.
- استبعاد Phone Link وVoicemeeter كليًا من التنفيذ الجديد.
- لا يعتمد التصميم على LiveKit، ولا على تطبيق موبايل.
- لكل شركة رقم موبايل خدمة مستقل للوارد والصادر. التصميم يدعم إضافة أرقام لاحقًا، مع ربط واضح بين الرقم والشريحة أو خدمة المشغل والشركة والإيجنت.
- البيانات وقوائم العملاء والمعرفة والتسجيلات والمهام والاعتمادات والجداول معزولة بين الشركات.
- مفاتيح AI والموديلات وتوجيهها تديرها OnTrack فقط في لوحة المنصة. بيانات اتصال الشركة الهاتفية منفصلة عنها.
- النطاق يشمل الوارد والصادر الآلي. التشغيل الصادر الأساسي متتابع: مكالمة ثم فاصل ثم المكالمة التالية لكل موظف، مع إمكانية توسيع السعة لاحقًا.
- نقطة المدير معتمدة كمتطلب مؤجل؛ لا نفتح تنفيذ أوامر إدارية في مرحلة إثبات الاتصال.
- لا أسعار نهائية أو مدة تسليم ثابتة قبل اختبار خط الاتصال وتحديد السعة.

## 3. ما نحتفظ به من الكود وما نطوره

| المصدر الحالي | استخدامه في التنفيذ |
|---|---|
| lib/OutboundMission.php | إعادة استخدام قواعد تكوين المهمة والتحقق منها، وتطويرها لإصدارات مهام محفوظة لكل شركة. |
| assets/outbound.mjs | مراجعة قواعد بداية الحوار وانتظار العميل؛ إعادة استخدام المنطق المناسب مع استبدال اعتماد التفعيل اليدوي بأحداث الهاتف. |
| api/live_session.php | الاحتفاظ بفكرة بناء تعليمات الجلسة وربط Gemini، ونقل مسؤولية جلسة المكالمة الهاتفية إلى خدمة السيرفر. |
| assets/app.js | الاستفادة من منطق معالجة الصوت وأحداث Gemini؛ استبدال getUserMedia وAudioContext في مسار الهاتف بمدخل ومخرج صوت من السنترال. لا يعمل الملف كما هو داخل السيرفر. |
| data/knowledge.json | مرجع للديمو فقط؛ قاعدة المعرفة الإنتاجية تأتي من مصادر الشركة داخل المنصة. |
| assets/app.css وindex.php | الاستفادة من عناصر العرض الملائمة بعد دمجها في تصميم المنصة العربي، دون الاعتماد على صفحة الديمو لتشغيل المكالمة. |
| tests الحالية | مراجعة وإعادة استخدام اختبارات المهمة المناسبة؛ اختبارات الصوت الوهمي لا تثبت نجاح مكالمة تليفون. |

تبقى صفحة تجربة صوت المتصفح اختيارية للاختبار. لا تصبح الصفحة شرطًا للمكالمات الآلية. لا تنقل أدوات التطوير أو نسخ الإعدادات المحلية أو النسخ الاحتياطية من الأرشيف إلى المنتج الجديد.

## 4. المعمارية المقترحة

| المكون | التقنية المقترحة | المسؤولية |
|---|---|---|
| لوحة المنصة وواجهات الأعمال | Laravel + Vue وفق مشروع Agent Builder | الشركات، الصلاحيات، الأرقام، الوكلاء، المعرفة، القوائم، الحملات، الجداول والتقارير. |
| تخزين الحالة | MySQL | المصدر الدائم لحالة المكالمات والقوائم والملاحظات وإصدارات المهمة. |
| تشغيل الأعمال المجدولة | Laravel Scheduler + Queues + Redis | اختيار العمل المستحق، الأقفال، إعادة المحاولة، والاستئناف. |
| التحكم الهاتفي | Asterisk بواجهة ARI | الوارد والصادر، طلب الرقم، الجسور الصوتية، إنهاء المكالمة وأحداث حالتها. |
| وصلة الصوت المباشرة | خدمة Node.js / TypeScript طويلة التشغيل | ربط صوت المكالمة بـGemini، تحويل الترميز، إدارة المقاطعة والجلسة، وإرسال أحداث الأعمال للمنصة. |
| الربط بسنترال الصوت | chan_websocket على نسخة Asterisk تدعمه | تبادل صوت المكالمة مع خدمة الصوت دون الاعتماد على المتصفح. |
| رقم الخدمة | شريحة موبايل تخص الشركة ومشغلها | رقم الموبايل الحقيقي والاتصال الخلوي والوارد والصادر. |
| ربط الشريحة بالسنترال | GSM/VoLTE Gateway يدعم المشغل | تحويل صوت المحمول وإشارات المكالمة إلى SIP بين الجهاز وAsterisk. ربط مباشر من المشغل بديل عند توفره والتحقق منه. |
| تحديث الداشبورد | Laravel Broadcasting / WebSockets | تحديث حالة الموظف والمكالمة والملاحظات دون تحديث الصفحة. |
| التسجيلات إن فُعلت | تخزين ملفات خاص | وصول مصرح به وروابط مؤقتة وسياسة احتفاظ قابلة للضبط. |

خدمة الصوت والسنترال يحتاجان بيئة تسمح بعمليات طويلة التشغيل واتصال الصوت والشبكة؛ لا يوضع تشغيلهما داخل طلب PHP عادي. إذا استضافت لوحة Laravel على استضافة مشتركة، يشغل جزء الهاتف والصوت في خدمة أو خادم مناسب منفصل.

الاتصال الوارد عبر الشريحة: شبكة المحمول توصل الاتصال إلى شريحة الشركة داخل GSM/VoLTE Gateway، ثم ينقله الجهاز عبر SIP إلى Asterisk، ثم وصلة الصوت وGemini. يعود الصوت عبر المسار نفسه.

الاتصال الصادر عبر الشريحة: المجدول يطلب من Asterisk استخدام قناة الشريحة المربوطة بالشركة. يطلب الجهاز رقم العميل عبر شبكة المحمول من الشريحة نفسها؛ بعد تحقق إجابة الطرف البعيد تربط المكالمة بجلسة الإيجنت. لا نعتمد على إجابة قناة داخلية أو بدء الرنين كدليل أن العميل رد.

## 5. ربط رقم موبايل مستقل لكل شركة

مسار الإطلاق المقترح: شريحة موبايل تخص الشركة داخل GSM/VoLTE Gateway متوافق مع شبكة المشغل، ثم ربط الجهاز بالسنترال عبر SIP. لا توضع الشريحة في الهاتف الشخصي ولا يحتاج التشغيل تطبيق موبايل. موقع الجهاز نفسه يحتاج كهرباء وتغطية محمول واتصال بيانات مناسبًا للوصول لخدمة الصوت.

يمكن وضع الجهاز لدى الشركة، أو إدارة تجهيزات مركزية وفق اتفاق تشغيل مناسب. تبقى كل شريحة وقناتها مربوطة بشركة واحدة، ولا يجوز أن يستخدم اتصال شركة شريحة شركة أخرى. نحدد مكان الأجهزة وملكيتها وإدارتها بعد تجربة التشغيل وحساب التكلفة.

البديل: خدمة مباشرة من مشغل المحمول تربط رقم الموبايل عبر SIP أو API صوتي يدعم الاتجاهين؛ لا نفترض توفرها لخط عادي ولا نعد بها قبل عرض موثق واختبار. باقة بيانات الإنترنت أو وجود eSIM وحدهما لا يتيحان صوت مكالمة المحمول للإيجنت.

توفر OnTrack للعميل شاشة لحالة الرقم والإيجنت والسعة، بينما تبقى إعدادات الربط الفنية الحساسة ضمن صلاحيات محددة. واجهة ربط الخط منفصلة عن مفاتيح مزود AI التي لا يراها العميل.

قبل اختيار مزود الرقم نثبت:

1. أنه رقم موبايل فعلي يخص الشركة، وأن الشريحة أو خدمة المشغل تدعم الوارد والصادر معًا.
2. أن الرقم الصادر مصرح به ويظهر بالشكل الصحيح لدى الجهة المستقبلة، بما تسمح به الشبكة.
3. توافق ترددات الجهاز وVoLTE واعتماده ودعم المشغل وشروط تشغيله، ومكان تركيبه والتغطية والطاقة وطريقة ربطه بالسيرفر.
4. أحداث الرنين والإجابة والإنهاء وأسباب فشل الاتصال.
5. عدد قنوات الصوت النشطة فعليًا، وليس عدد فتحات الشرائح وحده، وحدود إنشاء المكالمات وسلوك الوارد أثناء انشغال الشريحة.
6. الترميزات ودعم DTMF وخيارات التحويل لموظف.
7. الرسوم والتقريب المحاسبي وتفاصيل الاستخدام.
8. إمكانية استخدام الخدمة ضمن نموذج المنصة متعددة الشركات؛ الأرقام الكثيرة في عرض واحد لا تعني تلقائيًا إمكانية توزيعها على شركات مستقلة.

تذكر Dinstar في مواصفات UC2000-VE الربط بين المحمول وSIP ودعم VoLTE وقنوات صوت متعددة. الجهاز مثال على فئة الحل وليس اختيار شراء محسومًا أو إثباتًا لتوافق كل نسخة مع أي مشغل مصري. خدمات SIP للأرقام الثابتة لا تحقق وحدها شرط رقم الموبايل المعتمد هنا.

لا نخزن الرقم كحقل عرض فقط: له ربط فعلي بقناة شريحة محددة أو خدمة مشغل موثقة واختبارات اتصال. حالته تكون غير مهيأ، قيد الاختبار، موثق للوارد، موثق للصادر، نشط، أو موقوف؛ لا يظهر متصلًا قبل الدليل.

## 6. الموظف والمعرفة والمهام

لكل موظف: اسم وشخصية وأسلوب وصوت ودور، وربط برقم الخدمة، ومصادر معرفة تخص الشركة، ومهمة أو مهام متعددة.

لكل مهمة: اسم ووصف وهدف وافتتاحية ومعلومات مطلوبة من العميل وحدود تفاوض وشروط تصعيد ونتائج متوقعة. يمكن بدء إعداد المهمة بنص حر مثل الكود الحالي، مع حفظه وإصداره في قاعدة البيانات بدل فقده عند تحديث الصفحة.

تحدد المهمة لكل قائمة أو حملة، أو بقواعد صريحة قابلة للعرض. لا يختار الإيجنت المهمة عشوائيًا. عند بدء المكالمة نثبت نسخة المهمة والمعرفة المستخدمة في سجلها، حتى لا تتغير مكالمة قائمة بسبب تعديل الإعدادات.

مصادر المعرفة المشتركة تخص الشركة فقط، ويمكن تخصيص مصادر لمهمة أو إيجنت. النصوص القديمة لخدمات الاستضافة لا تفرض على شركات العقارات أو غيرها. أي فعل مالي أو تعديل نظام يخضع لتحقق السيرفر، ولا يعتمد على تعليمات النموذج وحدها.

## 7. إدخال قوائم العملاء

المدخلات: CSV، Excel بصيغتي XLSX وXLS، TXT، أو لصق أرقام كل رقم في سطر.

تدفق الاستيراد: قراءة ومعاينة ← اختيار عمود الرقم عند الحاجة ← اختيار الدولة الافتراضية ← مراجعة الصالح والخاطئ والمكرر ← اعتماد القائمة وربطها بالمهمة.

- الاحتفاظ بالمدخل الأصلي مع الرقم الموحد؛ لا نخمن رقمًا ضاع جزء منه بسبب تنسيق Excel أو ترميزه العلمي.
- دعم الاسم وحقول إضافية اختيارية دون فرضها على ملف أرقام فقط.
- كشف التكرار داخل الشركة والقائمة. نفس الرقم عند شركتين لا يخلط بياناتهما.
- عدم إسقاط المكرر أو استبدال بيانات عميل سابق دون سياسة ظاهرة عند الاستيراد.
- عرض عدد الأرقام المقبولة والمرفوضة مع سبب كل رفض.
- فحص قائمة عدم الاتصال الخاصة بالشركة قبل الإدراج وقبل بدء الاتصال.

## 8. الدوام والتشغيل المتتابع

الإعدادات: المنطقة الزمنية للشركة، أيام العمل، فترة أو فترات الدوام، الإجازة الأسبوعية، تواريخ العطلات، استثناءات العمل، وقت الرنين الأقصى، حد مدة المكالمة، والفاصل بعد المكالمة.

إعدادات منفصلة لإعادة المحاولة عند مشغول أو لم يرد: العدد الأقصى، الفاصل، الموعد المسموح، والأولوية مقارنة بالأرقام الجديدة. لا تعني إعادة تشغيل السيرفر إعادة الاتصال تلقائيًا بنفس العميل.

قبل كل مكالمة يفحص السيرفر: الشركة والرقم نشطان، الحملة تعمل، الوقت داخل نافذة العمل، اليوم ليس عطلة، الرقم صالح وغير مستبعد، لم تبدأ محاولة أخرى له، السعة متاحة، الحصة والرصيد يسمحان.

بعد نهاية المكالمة الفعلية يحفظ ended_at، ويحسب next_call_at = ended_at + delay. ينتقل إلى أول موعد عمل صالح إن وقع الموعد خارج الدوام. يستخدم موعدًا محفوظًا ومهمة مؤجلة، وليس انتظارًا داخل صفحة المتصفح.

نهاية الدوام تمنع بدء اتصال صادر جديد؛ المكالمة القائمة تستمر ما لم يوجد حد أو إجراء صريح لإنهائها. يمكن إعداد الوارد على مدار اليوم أو داخل الدوام بسياسة مستقلة. للمستخدم زران منفصلان: إيقاف بدء اتصالات جديدة، وإنهاء المكالمة الحالية.

النسخة الأساسية موظف واحد يجري مكالمة صادرة واحدة في الوقت نفسه. في مسار الشريحة نخطط مبدئيًا لمكالمة صوت نشطة واحدة لكل قناة شريحة، ولا نفترض أن الرقم نفسه يدعم واردًا وصادرًا متزامنين. نختبر انتظار المكالمة أو التحويل أو الانشغال وفق المشغل والجهاز؛ ثم نحدد السياسة في الواجهة. حجز سعة مستقلة للوارد يتطلب قنوات أو أرقامًا إضافية أو خدمة مشغل تدعم ذلك، ولا يتحقق بإعداد برمجي فقط.

## 9. الصوت وإنهاء المكالمة

وصلة الصوت تستقبل صوت العميل من السنترال، وتحوله لصيغة إدخال Gemini المدعومة، ثم تحول رد Gemini لصيغة السنترال. نختبر ترتيب الصوت والتوقيت والـbuffering والمقاطعة ومنع إعادة إرسال صوت الإيجنت إلى نفسه.

تظل اللغة وشخصية الإيجنت وفق إعداداته الحالية. لا نضيف محرك STT/TTS منفصلًا افتراضيًا؛ نستفيد من Gemini Live الذي يستهلك وينتج الصوت. نصوص المحادثة والتقرير لا تعني بالضرورة وصول كل كلمة لحظيًا دون تأخير.

بدء الرنين لا يفعّل محادثة العميل. إجابة المكالمة لا تثبت أن المتحدث إنسان؛ التعامل مع البريد الصوتي والرد الآلي يختبر وله سياسة مستقلة.

الوداع النصي لا يساوي انقطاع الخط. نضيف طلب إنهاء مكالمة من الإيجنت عبر أداة محددة يتحقق منها السيرفر، ثم ينتظر انتهاء الصوت اللازم ويرسل إنهاء للسنترال. إذا أغلق العميل، تنتهي جلسة Gemini ويتوقف احتسابها الداخلي فور المعالجة. عند انقطاع AI نطبق مسار فشل واضح، لا نترك اتصالًا مفتوحًا بلا حد.

## 10. الحالات والملاحظات والتقارير

| نوع الحالة | أمثلة |
|---|---|
| حالة الموظف | خارج الدوام، جاهز، يحاول الاتصال، في مكالمة، ينتظر الفاصل، متوقف مؤقتًا، خطأ يحتاج تدخلًا. |
| حالة محاولة الاتصال | محجوزة، طلب الاتصال جارٍ، يرن، أجاب، انتهى، مشغول، لم يرد، فشل، ملغى، نتيجة غير محسومة قيد المطابقة. |
| نتيجة الحوار | مهتم، غير مهتم، متابعة لاحقًا، طلب موظف، موعد مقترح، عدم الاتصال مجددًا، غير محدد. |

البيانات المستخلصة أثناء المكالمة تظهر كملاحظات أولية قابلة للتحديث، مع مصدرها وتوقيتها. بعد النهاية يبنى تقرير نهائي مرتبط بنص المكالمة. المعلومة التي لم يقلها العميل تظل غير مذكورة. الفشل في توليد التقرير لا يمحو سجل المكالمة ولا يؤدي لإعادة الاتصال بالعميل.

التقرير يتضمن: الشركة، الرقم المستخدم، الموظف، المهمة ونسختها، العميل، الوارد أو الصادر، الأزمنة والمدة، سبب النهاية، النص، الملخص، المعلومات المستخلصة، النتيجة، المتابعة المطلوبة، والتسجيل إن كان مفعّلًا.

النتيجة الآلية قابلة لتصحيح الموظف البشري مع سجل تعديلات. حقول التقرير تختلف حسب المهمة؛ العقارات مثال وليس نوع المنتج الافتراضي. يميز التقرير الموعد المقترح عن الموعد الذي تم تأكيده فعليًا بنظام الحجز.

## 12. نموذج البيانات وعقود الخدمات

يضاف إلى الكيانات القائمة، مع tenant_id وروابط الملكية المناسبة:

- voice_connections، voice_numbers، voice_number_agent_bindings، voice_gateways، voice_gateway_channels؛ مع ربط كل قناة شريحة بالشركة ورقم الموبايل الموثقين دون كشف معرفات الشريحة الحساسة للواجهة.
- voice_employee_configs المرتبطة بالوكلاء الأساسيين؛ لا نكرر هوية الوكيل دون حاجة.
- voice_tasks، voice_task_revisions، voice_task_knowledge_bindings.
- contact_imports، contact_import_rows، contact_lists، contact_list_members؛ تستفيد من contacts وcontact_identities الموجودة.
- voice_campaigns، voice_campaign_targets، voice_work_schedules، voice_schedule_exceptions.
- voice_calls، voice_call_attempts، voice_call_events.
- voice_transcript_segments، voice_notes، voice_reports، voice_followups.
- voice_recordings، voice_usage_events، voice_suppression_entries.

واجهة الطلب تقبل معرفات موارد داخل الشركة، ولا تسمح للمتصفح أو النموذج بتحديد شركة أخرى أو Caller ID عشوائي. خدمة الصوت تستلم تذكرة جلسة موقعة قصيرة العمر تخص مكالمة وشركة محددتين، وتحمل أقل سياق لازم.

طلب إنشاء مكالمة يرد بمعرف محاولة وحالة معلقة؛ الإجابة والنهاية تأتي من أحداث الهاتف. بيانات الربط والموديل والمفاتيح لا ترسل إلى لوحة العميل. أحداث الصوت غير مناسبة للمرور عبر طلبات PHP المتكررة؛ Laravel يتعامل مع التحكم والأحداث التجارية.

## 13. منع التداخل والتكرار والاستئناف

- ربط الشركة في الوارد يعتمد على رقم الخدمة وإعداد اتصال موثق؛ رقم المتصل لا يحدد الشركة ولا يمنحه صلاحيات إدارية.
- قفل وحجز محاولة الاتصال داخل معاملة قبل إرسال أمر السنترال، مع معرف ثابت للمطابقة.
- عند مهلة انتظار أو عطل بعد إرسال أمر الطلب، نطابق المحاولة مع السنترال قبل أي إعادة؛ لا نفترض فشل الاتصال ولا نعد بضمان exactly-once من الشبكة.
- نعالج أحداث الهاتف المكررة أو غير المرتبة دون تكرار التقرير أو الخصم أو الاتصال التالي.
- يظل العمل معروفًا بعد إعادة التشغيل. الحالات غير المحسومة تظهر للمراجعة بدل الاتصال العشوائي.
- كل مكالمة لها جلسة صوت وسياق معرفة منفصلان. يمنع أي مزج للصوت أو النص أو مفاتيح الاتصال بين شركتين.
- عزل ملفات التسجيل، البحث، التصدير، الواجهات، الطوابير والبث المباشر باختبارات عملية.
- حماية اتصال السنترال وخدمة الصوت بمصادقة وشبكة مقيدة، مع إخفاء الاعتمادات من السجلات.

## 14. الاستهلاك والتشغيل

يفصل النظام بين تكلفة الاتصال وتكلفة AI والتسجيل والتخزين عند تفعيلها. يحصل العميل على استهلاكه المسموح عرضه، وتبقى تكلفة المورد وهوامش OnTrack داخل لوحة الإدارة فقط.

تضبط حدود القنوات والمدة والمحاولات والرصيد على السيرفر قبل الطلب، وبسياسة واضحة للمكالمة القائمة عند نفاد الحد. الفوترة النهائية تقارن بسجل المزود لأن تقريب الدقيقة وأسباب التحصيل تختلف حسب العقد.

نراقب فشل الطلب، زمن بدء الرد، تقطع الصوت، انقطاع Gemini، محاولات الاتصال غير المحسومة وتراكم التقارير. يجهز إيقاف عام للاتصالات الصادرة أو إيقاف شركة واحدة دون تعطيل الشركات الأخرى.

## 15. مراحل التنفيذ ومعيار نجاح كل مرحلة

| المرحلة | التنفيذ | شرط الإغلاق |
|---|---|---|
| 0 — تثبيت الأساس | حفظ الكود الحالي، تحديد الأجزاء القابلة لإعادة الاستخدام، مراجعة بيئة التشغيل، وتثبيت إعداد الشركة والرقم التجريبي. | مصدر معروف وخطة إعداد قابلة للتنفيذ، دون تغيير سلوك الديمو العامل. |
| 1 — إثبات الهاتف | شريحة ورقم موبايل واحد، Gateway متوافق وربط SIP إلى Asterisk، وصلة Gemini مباشرة، وارد وصادر على أرقام اختبار محددة. | شخص يرن على رقم الموبايل فيرد الإيجنت، والإيجنت يتصل من الشريحة نفسها ويجري حوارًا ثنائي الاتجاه، مع التقاط الإجابة والنهاية والتحقق من ظهور الرقم. |
| 2 — الدمج والعزل | ربط شركتين بأرقام أو مسارات اختبار منفصلة، تحميل المهمة والمعرفة من المنصة، حفظ المكالمات وعرضها. | لا تنتقل بيانات أو صلاحيات أو صوت بين الشركتين، ولا يستطيع عميل اختيار رقم شركة أخرى. |
| 3 — القوائم والموظف | الاستيراد بكل الصيغ المتفق عليها، المهام المتعددة وربطها، وقائمة الاتصال المتتابعة والفاصل. | يعالج قائمة اختبار دون تكرار غير مقصود، ويحترم الفاصل بعد النهاية الفعلية. |
| 4 — الجدولة والاستئناف | أيام العمل والعطلات والمنطقة الزمنية والإيقاف وإعادة المحاولة والاستئناف بعد العطل. | يعمل والمتصفح مغلق، لا يبدأ خارج الدوام، ولا يعيد طلب رقم لمجرد إعادة التشغيل. |
| 5 — المتابعة والتقارير | ملاحظات أثناء الحديث، تقرير نهائي، نتائج منفصلة عن حالة الخط، وتسجيل اختياري. | تقرير مطابق للمحادثة، لا يختلق حقولًا، وفشل التقرير لا يعيد المكالمة. |
| 6 — اختبار السعة والتشغيل | حصص العملاء، الوارد أثناء الصادر، فشل المزود، مراقبة، احتساب استخدام ومطابقة الأحداث. | حمل اختباري موثق ضمن القنوات المتاحة، وعدم خلط الشركات أو تكرار الفوترة. |

اختبار الاتصال في المرحلة الأولى مانع لتوسيع الإطلاق، لكنه لا يمنع تطوير القوائم والجداول والواجهات باختبارات محلية موصوفة بوضوح. لا توصف المحاكاة بأنها اتصال حي.

## 16. مصفوفة قبول مختصرة

1. الاتصال الوارد لرقم الشركة A يفتح إيجنت ومعرفة A فقط.
2. اتصال A الصادر يستخدم شريحة ورقم موبايل A الفعليين أو خدمة مشغل موثقة له؛ لا يسمح برقم ظاهر وهمي أو استخدام قناة B.
3. موظف أو طلب أو job تابع لـA لا يقرأ أو يغير مكالمة B.
4. تعمل محادثة مصرية مع مقاطعة وصمت وإنهاء من العميل دون استمرار جلسة مكلفة بلا حد.
5. تتحول ملفات CSV وXLSX وXLS وTXT والنص الملصوق إلى قائمة مراجعة صحيحة؛ الأرقام المشوهة لا تصلح بالتخمين.
6. اختيار مهمة القائمة يحدد سياق المكالمة، وتعديل المهمة لا يبدل جلسة قائمة.
7. لا يبدأ اتصال جديد قبل انتهاء المكالمة والفاصل؛ وقت نهاية الدوام والعطلات يعاد فحصه لحظة الطلب.
8. سياسة لم يرد تختلف عن الفاصل العادي، وتحترم الحد الأقصى للمحاولات.
9. إغلاق المتصفح لا يوقف الموظف؛ إعادة تشغيل الخدمات لا تؤدي لمكالمة مكررة غير محسومة.
10. أحداث الإجابة والنهاية المكررة أو المتأخرة لا تكرر التقرير أو الخصم أو الانتقال للرقم التالي.
11. حالة اتصال ناجح لا تعني عميلًا مهتمًا؛ البيانات غير المذكورة تظل غير مذكورة.
12. يختبر الوارد أثناء اتصال صادر من الشريحة نفسها، وتعرض السياسة الفعلية للانشغال أو الانتظار أو التحويل؛ لا ندعي أن الرقم يدعم مكالمات متزامنة دون إثبات من المشغل والجهاز.
13. مؤشرات استهلاك العميل لا تكشف مفاتيح أو أسماء موديلات أو تكلفة المورد الداخلية.

## 17. متطلب المدير — محفوظ للتصميم اللاحق

لكل شركة رقم مدير محدد، وملف تعريف ومعلومات وصلاحيات داخل حساب الشركة. المطلوب لاحقًا أن يستطيع الاستفسار عن معلومات النظام وتنفيذ أوامر مسموحة بالصوت.

تصمم الهوية والتحقق قبل إعطاء الصلاحيات؛ Caller ID وحده ليس إثبات هوية كافيًا. الأوامر الحساسة لها صلاحيات وتأكيد وتنفيذ موثق. لا يبدأ تطوير أدوات المدير أو صلاحيات واسعة ضمن مرحلة إثبات الاتصال.
