# تنظيم المستودع والنشر

## التقسيم المعتمد الآن

الكود القائم للديمو يبقى في الجذر: api/assets/lib/index.php وغيرها، كي لا نكسر مسارات المستخدم الحالية بمجرد توثيق المشروع. docs مرجع متطور، reference نسخ واردة مستقلة لا تُعدّل باعتبارها كود الإنتاج، ops قناة الإدارة، tools أدوات التحقق. عند بدء Laravel لاحقًا يحدد انتقال الكود بعقد ترحيل مستقل واختبار، ولا ينشأ تطبيق فارغ فوق الجذر بالتخمين.

المستودع Private بحسب GitHub metadata. الحفاظ على الخصوصية لا يلغي حماية الاعتمادات. لا تحويل Public ولا نشر صفحات GitHub Pages أو مشاركة ملفات خاصة من دون طلب.

## الفروع

- `main`: مرجع الكود والخطط والوثائق، نقطة الدخول الافتراضية.
- `ontrack-host-link`: الفرع الذي يقرأه العامل المثبت ويكتب تقاريره فيه. هو المصدر الحي للطابور/النتائج، حتى لو نسخة منها موجودة في main.
- عند إدماج هذا التنظيم تُحفظ histories وبيانات الفرعين دون force reset. لا تستبدل reports الحية بنسخة docs قديمة.
- مستقبلًا تغييرات المنتج الكبيرة بفرع عمل وreview/test، ثم قرار نشر مناسب. طلب المستخدم الحالي يجيز تجهيز المرجع ورفعه؛ لا يعني نشر كل الملفات على public_html.

## ممنوع ضمن artifact النشر العام

docs/، reference/، ops/، tools/، AGENTS.md، CLAUDE.md، ملفات Git، ZIPs، تقارير التحكم، screenshots، config.json للعامل، أسرار .env والمفاتيح الخاصة ونسخ backups.

مجلدات docs/reference/ops/tools تتضمن `.htaccess` مانعًا للوصول على Apache/LiteSpeed كحماية إضافية عند نسخها بالخطأ، لكن الاستبعاد من deploy هو الأساس. هذا لا يفترض أن Nginx يقرأ .htaccess.

المسار التشغيلي للعامل خارج public_html. لا تنقل العامل إلى endpoint PHP عام باسم shell.php أو dev endpoint؛ GitHub pull كافٍ للإدارة الحالية.

## المرفقات والتاريخ

Agent Builder v1.3 محفوظ بالكامل مع أرشيفه الأصلي. voicecall محفوظ كنسخة منقحة لا تتضمن المفتاح المحلي أو backups المحتوية على أسرار محتملة. manifests تسجل اسم وبصمة كل مدخل، هل نقل كما هو أو حُجب سر أو لم ينقل، ورابط الأصل في المرفقات. لا حذف صامت أو وصف النسخة المنقحة بأنها byte-identical للأصل.

المقترحات التاريخية محفوظة في history مع تنبيه واضح. أحدث القرارات تتقدم عليها. لا يعاد تطبيق «لا تطبيق موبايل» أو شراء Gateway اعتمادًا على خطة قديمة.

## تحديث جلسة التطوير

اقرأ الحالة قبل العمل. بعده حدث CURRENT_STATE/JSON وCHANGELOG وأضف evidence مناسبة. إذا حدث تعارض بين الجلسة وGit، اقرأ الحالة الحالية ولا تستبدلها بقصة المحادثة القديمة. وثق العوائق والاختبارات وحدودها، ولا تحفظ PAT أو private key تحت مسمى memory.
